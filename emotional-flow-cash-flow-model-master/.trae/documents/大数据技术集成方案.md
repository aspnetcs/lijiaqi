# 大数据技术集成方案（Hadoop/HDFS + PySpark）

## Context

用户要求为毕业设计量化系统加入大数据技术（Hadoop/HDFS）。登录注册+图片验证码已存在（FastAPI web 层），无需重做；核心增量是把 **Hadoop 3.3.6 伪分布式（真 HDFS）+ PySpark** 集成进系统：HDFS 作为旁路存储与登录审计日志通道，PySpark 做全市场批量因子计算，Web 仪表盘新增"大数据平台"面板。用户已确认选择完整伪分布式方案（方案 A）。

环境现状：Windows 11、JDK 11.0.23 位于 `F:\jdk11.0.23`（JAVA_HOME 未配置）、无 Docker、无 Hadoop、无 PySpark。

## 第一阶段：环境安装（Shell 脚本 + setx）

1. **环境变量**（注册表 setx，用户级）：
   - `JAVA_HOME=F:\jdk11.0.23`（修复现存错误配置）
   - `HADOOP_HOME=D:\hadoop-3.3.6`；Path 追加 `%JAVA_HOME%\bin`、`%HADOOP_HOME%\bin`、`%HADOOP_HOME%\sbin`
2. **下载**：清华镜像 `mirrors.tuna.tsinghua.edu.cn/apache/hadoop/common/hadoop-3.3.6/` 下载 tar.gz（~700MB，沙箱外），tar 解压至 `D:\hadoop-3.3.6`
3. **winutils**：gitee/cdarlint 镜像取 winutils.exe + hadoop.dll → `D:\hadoop-3.3.6\bin`，hadoop.dll 复制到 `C:\Windows\System32`
4. **配置**：
   - `hadoop-env.cmd`：`set JAVA_HOME=F:\jdk11.0.23`
   - `core-site.xml`：`fs.defaultFS=hdfs://localhost:9000`，`hadoop.tmp.dir=D:/hadoopdata/tmp`
   - `hdfs-site.xml`：`dfs.namenode.name.dir=D:/hadoopdata/namenode`、`dfs.datanode.data.dir=D:/hadoopdata/datanode`、`dfs.replication=1`、`dfs.webhdfs.enabled=true`
5. **初始化**：`hadoop namenode -format` → `start-dfs.cmd` → 验证 9870 Web UI
6. **PySpark**：`pip install pyspark==3.3.6`（与 Hadoop 同版本）

## 第二阶段：数据上 HDFS

- `data/upload_to_hdfs.py`：`hadoop fs -put` 上传 `D:/开发/训练数据/` 的 6 个 parquet 目录至 `/quant/data/`，初始化 `/quant/logs/login/`、`/quant/results/`

## 第三阶段：代码（全部新增，零破坏）

| 文件 | 职责 |
|---|---|
| `src/bigdata/hdfs_client.py`（新建） | WebHDFS REST 封装（requests）：`write/read/append/exists/upload`，两段式 CREATE，避免 Windows libhdfs native 依赖 |
| `src/bigdata/spark_jobs.py`（新建） | Spark job：`get_spark()` 单例（local[*]）；Job1 全市场因子计算（读 `/quant/data/stock_daily_pq/` → 20日动量/波动率/量比 → 写 `/quant/results/factors/` + 汇总 JSON）；Job2 数据质量聚合（缺失值/涨跌幅越界按 symbol 统计 → `/quant/results/quality/`） |
| `src/bigdata/login_audit.py`（新建） | `log_login_event(username, ip, success)` 追加 JSON 到 `/quant/logs/login/`；try/except 包裹，HDFS 不可用时仅警告、不阻塞登录 |
| `src/config.py`（修改） | 新增 `BigDataConfig`（hdfs_host/hdfs_web_port/路径常量），合入 `SystemConfig` |
| `web/app.py`（修改，约3行） | login() L176 `db.update_last_login(...)` 后插入 `login_audit.log_login_event(...)`；新增受保护路由 `/api/bigdata/summary`（HDFS 状态+Spark 结果）、`/api/bigdata/logs`（登录日志统计），风格参照 L218-261 现有 /api/ |
| `web/templates/dashboard.html`（修改） | 复用 box/grid 布局新增"大数据平台"卡片（HDFS 状态、Spark 计算结果、登录日志计数） |

**零破坏原则**：DataReader/三引擎/MCP/现有 API 全部不动；HDFS 是旁路副本+日志通道，不接管主数据源；HDFS 不可用时新增功能静默降级（Spark job 路径可一行切回本地 parquet）。

## 第四阶段：验证

1. `start-dfs.cmd` + 9870 UI 可访问；`hdfs dfsadmin -report` 正常
2. `hadoop fs -ls /quant/data/` 6 目录齐全
3. `python src/bigdata/spark_jobs.py` Job1/Job2 出结果文件
4. 注册新用户登录 → `hdfs dfs -cat /quant/logs/login/` 有记录
5. `/api/bigdata/summary` 返回 JSON、dashboard 面板渲染
6. 回归：pytest 51/51 + MCP 8/8

## 风险与降级

- winutils 下载失败/版本不匹配 → gitee 镜像（3.3.5/3.3.6 二进制兼容）
- HDFS 启动失败（clusterID 不匹配等）→ 删 `D:/hadoopdata` 重新 format；hadoop.dll 必须进 System32
- 下载源优先级：清华 > gitee > 阿里云
- 端口 9000/9870 被占 → 改配置并同步 BigDataConfig
- 终极降级：仅 PySpark local 读本地 parquet（路径在 BigDataConfig 一行切换）
